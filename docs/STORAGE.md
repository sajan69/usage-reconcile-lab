# Storage and trust boundaries

DuckDB 2.0.0 and pytz 2026.5 are pinned. The schema stores snapshots, normalized application events, normalized provider totals and explicit provider bucket coverage. It stores no raw input bodies, prompt/completion text, signatures or credentials. Allowlisted labels can still be sensitive; choose them accordingly. Raw-byte and projection hashes plus canonical manifest/quality JSON provide reproducibility context without retaining raw extras.

An observation ID is SHA-256 of canonical adapter/schema version, normalized manifest and raw-input SHA-256. Reimporting the same bytes/context is a no-op. Changed bytes or acquisition context creates a separate observation, preserving prior rows. This identity is byte-sensitive; formatting changes can create another observation even with equal normalized records. Projection hashes include input order. No cross-observation event summation, correction merging or duplicate removal is implied.

Each import opens one transaction encompassing initial schema creation, metadata and all domain rows. Validation happens before database open. Failures roll back both metadata and rows; a first failed write may leave an empty database with no committed tables. A zero-byte existing file is refused rather than overwritten. A new database can remain after an operational failure; the command does not promise filesystem cleanup after I/O failures or physical power loss. Single writer only; lock conflicts surface as database errors without automatic retry.

Read-only inspection returns one snapshot's manifest, hashes and quality counts, never record bodies. It opens no missing database, validates the schema marker and uses a consistent transaction. Queries bind values; user SQL is not accepted. External SQL file/network access and automatic extension installation/loading are disabled; a test confirms file-table reads fail. Connections use two threads and a 256 MiB memory limit. These limits are not a general malicious-file sandbox.

Use a trusted local directory and trusted databases. New POSIX databases and generated files use mode 0600, generated directories 0700. Symlink database files, non-regular files and permissive existing POSIX databases are refused. Parent-directory races, hostile databases, administrators, backups and Windows ACLs remain outside this protection; Windows users must manage directory permissions. Database creation briefly unlinks the exclusively pre-created empty file because DuckDB requires a nonexistent path; trust in the parent directory is essential. The temporary process umask is another reason to run this CLI as a single-threaded local utility. Storage is not encrypted.

Python 3.11+ follows the [DuckDB Python requirements](https://duckdb.org/docs/2.0/clients/python/overview). No network collection, provider authentication, arbitrary callback URLs, telemetry or hosted service is implemented. Comparisons and report rendering are outside the ingestion commands; imported “complete” metadata is a declaration with bounded structural checks, not proof that application and provider populations match.
